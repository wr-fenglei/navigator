# 实施

主 agent 按总体计划从第一阶段推进, 维护循环之间的关系和执行结果

## 按阶段派发

先核对第一阶段的输入和资源, 如果缺条件就先补齐, 按依赖启动一个或多个循环, 修改范围和资源不冲突时并行, 尚不能启动的循环保留在计划中, 写明缺什么以及由哪个循环或外部条件补齐

用户已明确要求按循环新建任务时, 主 agent 为每个需要派发的循环创建一个新任务, 由该任务负责实施并调用 subagent 验证, 普通子任务使用 subagent, 不把技能本身当成任意新建任务的授权

派发时交代目标, 输入, 修改范围, 通过条件和任务记录的绝对路径, 保存任务标识与工作目录, 循环任务交回结果, 总体计划与记录由主 agent 更新, 循环定义和每次执行分开记录, 同一工作仍在执行时不重复派发, 并发量按工具实际支持安排

## 验证与重验

每个交付循环都由其执行任务另开独立 subagent 检查, 使用新上下文, 给它目标, 原定标准, 待验产物和必要的运行条件, 不预先给出实施者的结论, 由它独立检查并返回结果与依据, 不对验证者继续套用同样的分层派发

没有独立验证工具或暂时没有名额时, 保留为 "待验证", 说明原因并安排补验, 不把实施者自查当作独立验证, 主 agent 核对验证报告对应的产物后, 再触发条件已满足的后续循环

验证记录写清检查的是哪一版产物, 使用什么输入和环境, 这些条件没变且没有新疑点时, 可以使用这次通过结果

出现计划列出的变化时, 沿直接和间接依赖触发重验循环, 包括已经通过但受影响的结果, 旧验证不再作为通过依据, 暂停用它启动后续工作

已在执行的相关任务先核对是否需要暂停或修正, 重验通过后恢复相应依赖, 无法确认影响范围时, 先由进度核对循环查清

## 进度核对

结果交回, 计划或环境改变, 暂停或恢复时, 主 agent 核对本次变化涉及的工作, 更新同一份任务记录

- 做到了哪一步, 谁还在处理, 哪些操作已经完成
- 产物是哪一版, 检查是否通过, 结果在当前条件下是否仍然适用
- 哪些工作缺条件, 哪些需要补做或重验, 接下来能启动哪些循环

不确定就先查实际产物和执行情况, 查清前不重复操作, 恢复时先读当前情况, 有疑问再追查历史, 调整方案时关联促成决定的记录, 保留被替代的决定

循环使用以下状态, 以实际产物和工具返回为依据

- "待启动": 尚未开始
- "执行中": 已开始, 执行者仍在处理
- "待验证": 已有结果, 尚未确认通过, 或原结果需要重验
- "已通过": 结果符合该循环的通过条件
- "受阻": 缺少条件或遇到失败, 暂时不能继续

## 失败处理

局部失败先修复实现, 再按原有标准独立验证

路径或依赖失效时, 主 agent 先调整拆解并说明原因和受影响的循环

目标, 范围, 验收和授权不变, 且不涉及需要用户取舍的成本或风险变化, 就自行推进, 否则先给出调整方案, 请用户决定

重试需要新条件或明确的检查目的, 无新依据时记录阻塞, 向用户说明缺什么以及哪些循环还能继续, 继续推进不依赖该失败结果且具备启动条件的循环

## 暂停, 恢复与完成

用户暂停或停止时, 主 agent 停止派发并通知本任务执行者, 记录各循环已经做到哪一步, 还有哪些操作正在进行, 恢复时先运行进度核对循环, 再继续调度

用户要求稍后继续, 定时执行或监控时, 用当前环境提供的自动化工具创建或更新定时任务, 告诉它何时运行, 从哪份记录继续, 要检查或完成什么, 以及何时停止, 沿用已有验收, 授权和预算

保存工具返回的定时任务标识, 确认创建成功后再告诉用户已安排, 工具不可用就说明还未建立后续运行, 完成或停止时关闭本任务创建的定时任务并核对结果

后续运行无变化时保持安静, 有可处理的变化, 完成, 失败或需要用户决定时通知, 用户另有通知要求则沿用

交付时说明通过了哪些验收, 附上产物与验证记录, 主观体验交给用户确认, 未通过的说明剩余项与下一步
